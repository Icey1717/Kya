## Shared projection math: fog, AA, mip LOD, and flares

All four consumers must retain the **original GS projection's constant W term**. The game's GS camera uses `W = 1 - cameraZ / projectionDistance`; the native camera uses `W = -cameraZ`. A constant Q multiplier or a linear near/far depth conversion cannot generally bridge these projections. Adjusting TEX1 K or fog strength would hide the conversion error for only some distances.

For a projection with depth numerator `a * cameraZ + b` and clip W `c * cameraZ + d`, native depth `n` recovers `cameraZ = (bNative - n * dNative) / (n * cNative - aNative)`. [GsProjection.h](../port/Windows/Renderer/include/GsProjection.h) expresses GS clip Z/W in the native clip Z/W basis once, producing a rational depth conversion plus two reciprocal-W coefficients. [gs_projection.glsl](../port/Windows/Renderer/Shaders/src/gs_projection.glsl) evaluates the same mappings in shaders.

| Consumer | Original GS quantity | Native implementation status |
| --- | --- | --- |
| Fog | GS depth `(aGS * cameraZ + bGS) / (cGS * cameraZ + dGS)` | Shared rational mapping; inverse mapping converts the adjusted GS depth back for depth writes. |
| PS2 AA approximation | GS depth for the blur mask | Same mapping as fog; FXAA does not consume depth. |
| Automatic mip LOD | GS `Q = 1 / abs(cGS * cameraZ + dGS)`, then `-log2(Q) * 2^L + K/16` | Shared coefficients reconstruct Q as `abs(gl_FragCoord.w / (u * gl_FragCoord.z + v))`, including nonproportional W rows and orthographic cameras. Fixed LOD does not consume Q. |
| Flare visibility | Native depth corresponding to the projected GS flare depth | Shared inverse rational mapping replaces the incorrect near/far lerp. Screen/marker sizing remains in GS coordinates. |

Implemented (2026-10-07): `GsProjection.h` replaces the fog-specific helper and the mip path's constant W ratio. Missing GS projections use native depth/Q unchanged; singular native depth rows also use that fallback. The helper assumes projection Z/W rows depend only on camera Z/W, as the game's perspective and orthographic cameras do; oblique depth planes depending on X/Y are outside this mapping.

Material submission snapshots `(u,v)` with each mesh instance, including shadow-camera restoration through `PushGlobalMatrices`. The 128-byte push layout is retained: `samplingParams` at offset 112 holds the GS Q denominator for ordinary textures, or UV scale for framebuffer materials. These material modes are exclusive; the former Q scale at offset 124 is now padding. Shader blend rules, TEX1 decoding, and effect-specific masks remain separate. Fog and AA also share the signed, saturating green-byte operation in [gs_depth.glsl](../port/Windows/Renderer/Shaders/src/gs_depth.glsl).

Preview replay retains the draw's original GS projection and recomputes Q coefficients for its replacement native camera. Reusing the main camera's coefficients with different near/far planes would misinterpret preview depth; missing GS projections still use the preview camera's native Q unchanged.

- [x] Share CPU coefficients and shader evaluation across fog, AA, mip LOD, and flare visibility; retain immutable draw/command state and the existing shadow-camera restoration.
- [x] Compare GS depth, Q, inverse depth, and flare projection against direct original-camera matrix projection across near/middle/far distances. `FogProjection.OriginalCameraWOffsetAndRoundTrip` covers the actual game projection; `GsProjection.OrthographicNativeRetainsGsWOffset` covers orthographic conversion.

## 3. Normal extrusion

Sources: strip flag `0x100`, `ANIM_ST_NORMAL_EXTRUDER_SPR`, and `ed3DPKTCopyMatrixPacket` in [ed3D.cpp](../src/b-witch/ed3D.cpp); embedded VU microcode in [OneTimeCommands.h](../src/Rendering/OneTimeCommands.h); [native vertex shader](../port/Windows/Renderer/Shaders/src/native.vert.glsl). - [x] Recover the extrusion operation, coordinate space, flag gating, and position relative to skinning/model transforms.
- [x] Consume the per-draw extrusion amount in the native vertex shader.
- [x] Preserve UV scrolling when both features are enabled.
- [ ] Validate zero, positive, and negative extrusion on static and animated geometry, including shared-mesh instances.

Implementation notes (2026-10-06):

- The embedded VU program gates extrusion on `vi01 & 0x100` at instruction `0x3b1`. Instructions `0x3b6`–`0x3c9` iterate vertex XYZ at `vi15 + 3`, with normals starting at `vi15 + 1 + 0xd8`, and load the animation/extrusion vector from VU address `0x21`. `MULz.xyzw vf04, vf02, vf01` (`0x3bf`) followed by `ADD.xyz vf05, vf03, vf04` (`0x3c3`) and `SQ.xyz` (`0x3c5`) implements `position.xyz += normal.xyz * animST.z`. There is no normalization, inverse-transpose transform, clamping, or displacement of position W. Signed decoded normals retain their magnitude; positive and negative amounts move along and against them.
- Rigid bone conversion first stores the transformed XYZ and normal XYZ in those buffers (`0x138`–`0x139` for the first vertex). Extrusion therefore uses the bone matrix's upper 3x3 for normals, then offsets the skinned position in object space before object-to-culling/clipping/screen transforms. Static vertices use their decoded object-space normal. The native mesh, shadow-mask, and shadow-receiver vertex shaders follow this ordering. Shadow shaders also use the captured animation base offset instead of assuming `0x3dc`; receiver descriptors now bind the existing animation/extrusion buffer at binding 5.
- `ed3DPKTCopyMatrixPacket` selects the hierarchy setup's `field_0x10` float when supplied, otherwise `FLOAT_00448a04` (default `0.01f`), and stores it in vector Z. Existing `PushMatrixPacket` / `PushAnimST` append per-draw vector data, and `RenderMesh` snapshots its buffer index and render flags for each instance. Cached mesh vertices remain unchanged, so shared meshes, later state changes, queued draws, alpha-fail replay, and preview replay retain each submission's amount. UV scrolling independently consumes XY under flag `0x200`, including shadow-mask texture sampling.
- Validation: `cmake --preset x64-debug`, the x64-debug build, existing `KyaPortTest` CTest target, and `spirv-val` for all three modified shaders pass. These checks establish build and shader validity, not visual parity. Runtime level/asset identification, zero/positive/negative static and rigid-animation GPU checks, shared-mesh instance comparisons, Vulkan validation, and representative PS2/native captures remain pending. The overview stays incomplete.
- Runtime diagnostic: debug builds log the first emitted main-pass draw with render flag `0x100`, including mesh name, extrusion amount, buffer index, and index count. It reports flag activation even when the amount is zero; recording a draw does not prove its pixels survive clipping, depth, or alpha tests.

## 4. Mipmaps / trilinear filtering

Sources: `ed3DFlushMaterial`, `TEX1`, `MIPTBP1`, and `MIPTBP2` in [ed3D.cpp](../src/b-witch/ed3D.cpp); texture upload/samplers in [TextureCache.cpp](../port/Windows/Renderer/Vulkan/src/Texture/TextureCache.cpp); one-level image allocation in [VulkanImage.cpp](../port/Windows/Renderer/Vulkan/src/Objects/VulkanImage.cpp).

- [x] Trace all stored mip levels through bitmap decoding, upload, image allocation, and image views.
- [x] Preserve authored mip levels where available; decide how textures without a chain behave from PS2 evidence.
- [x] Carry TEX1 filtering, maximum level, and LOD settings into sampler selection, accounting for differences from GS LOD calculation.
- [x] Support mip enable/disable and nearest/linear mip selection without regressing point-versus-linear base filtering.
- [x] Validate distant and oblique surfaces, mip transitions, alpha textures, and material switches against PS2 captures.

Implementation notes (2026-10-07):

- Debug > Rendering Debug > Renderer > Pipeline exposes **Force Highest Mip Level** and **Force Lowest Mip Level** (also in the standalone Rendering window). These persisted, mutually exclusive options select the smallest available authored mip or full-resolution mip zero for native textured meshes, overriding material mip limits and automatic/fixed LOD. Single-level textures stay at level zero; disabling the active option restores authored selection. The override is captured in sampler descriptors and push data during texture binding, preserving queued draws. The Vulkan regression checks both overrides, switching between them, disabling an inactive override, and restoring normal selection.
- `ProcessUploadCommandList` collects the actual image transfers before separating the final palette transfer. This preserves additional authored levels in assets whose bitmap header under-reports the transfer count. Each level receives its own reduced canvas dimensions. Per-layer material decoding retains TEX1, MIPTBP1, and MIPTBP2. The existing GS memory decoder uploads and expands each level with the shared CLUT, its transfer destination, reduced TEX0 dimensions, and MIPTBP texture pitch where supplied (otherwise a reduced base pitch). Native images allocate and expose every valid decoded level, up to the GS seven-level limit and the texture's final 1x1 level. Upload copies crop GS block padding and transition the entire chain.
- Textures without an authored chain remain single-level; no replacement mip chain is generated. `ed3DFlushMaterial` sets MXL from `(maxMipLevel - 1) * gbDoMipmap`, so a single-level bitmap and disabled mipmapping both select level zero. Samplers also clamp MXL to the available decoded levels, preventing access to missing levels. Texture replacement/resizing retains the authored lower levels, resampling each in normalized coordinates; reverting restores the original base image. Upscaled lower levels therefore retain authored detail rather than being regenerated from the replacement base.
- MMIN 0/1 selects point/linear base filtering; 2/3 selects point filtering with nearest/linear mip selection; 4/5 selects linear filtering with nearest/linear mip selection. MMAG independently controls point/linear magnification. The mapping follows [PCSX2's GS register definitions](https://github.com/PCSX2/pcsx2/blob/master/pcsx2/GS/GSRegs.h). Palette samplers have a separate cache identity and remain point-filtered at level zero. TEX1 is bridged both by the Windows packet-building macro and by material packet replay. Each native mesh instance snapshots TEX1 before queueing, retaining its own immutable sampler descriptor through later option changes, alpha-fail replay, and preview replay. Descriptor refresh preserves every sampler variant during texture resizing.
- Fixed LOD uses signed 12-bit K divided by 16. Automatic LOD uses GS `-log2(abs(Q)) * 2^L + K/16`. The original VU starts STQ.Q at one and divides it by GS clip W. Matrix submission captures the shared projection helper's two Q denominator coefficients per draw, retaining the original GS W offset and shadow-camera restoration. The fragment shader reconstructs GS Q from native depth and reciprocal W, avoiding dependence on UV derivatives or native resolution. Missing GS projections retain native Q. Negative LOD retains magnification selection; MXL and the available chain bound the mip range. LOD parameters occupy the upper bits of the existing global-alpha push word, with alpha retained in the low byte; Q coefficients use the material's `samplingParams`, preserving the 128-byte push layout. Native mesh and shadow-mask sampling share the implementation; framebuffer materials use `samplingParams` for their existing UV scaling instead. PS2 capture comparison remains necessary to establish visual parity.
- Validation: the x64-debug build, `TextureMipmaps` CPU regression tests, CTest, and `spirv-val` for all six native/shadow shaders pass. The opt-in `TextureMipmapRendering.DISABLED_AuthoredAlphaTrilinearQueuedStateAndResize` Vulkan test also passes with a hidden window and no emitted validation messages. It checks three distinct authored RGBA levels, fractional trilinear color/alpha, nearest mip selection, MXL disabling, independent point/linear magnification, TEX1 changes after mesh submission, and descriptor/chain preservation across replacement resizing and restoration. Automatic LOD checks use constant UVs, signed K=-140, nonproportional W rows, reciprocal clip W, L scaling, and coefficient changes after submission. Run it alone from `bin/WIN` with `./KyaPortTest.exe --gtest_also_run_disabled_tests --gtest_filter=TextureMipmapRendering.*`. User RenderDoc captures confirm three levels and mip-enabled TEX1 in the demo scene, including Actorheroprivate. Visual checks after the Q-based fix, distant/oblique surfaces, indexed-alpha texture captures, and representative PS2/native comparisons remain pending; the overview stays incomplete.

Implementation notes (2026-10-07):

- Ghidra confirms `ed3DFlushFogFX` (`002aeb40`), `ed3DFlushAAEffectPlane` (`002ae8b0`), `ed3DMoveRG2BA` (`002ae2b0`), `ed3DCorrectAlpha` (`002ad8d0`), and `ed3DFogScreen` (`002adfe0`). No additional vertex-fog path was identified in the audited submission code. The root scene dispatch runs fog after its geometry, children, and display list when `SCENE_FLAG_FOG_PROPERTY` is set and packets were emitted; it runs before AA and subsequent scenes. The native hook retains that dispatch, real property gate, current viewport/depth-surface checks, and normalized current viewport scissor.
- `field_0x4` is a signed adjustment to the depth buffer's green byte, not a world-space distance. The preliminary plane uses FRAME PSMZ32, FBMSK `0xffff00ff`, and FIX=128: positive values add (`ALPHA=0x8000000068`), negative values subtract (`ALPHA=0x8000000062`), with byte saturation and no carry into adjacent bytes. The PSMZ16-to-PSMCT16 shuffle reads eight-pixel strips and writes them eight pixels to the right over a doubled-height view. TEXA's zero TA0/TA1 clears the packed alpha bit. A CPU reference using the existing GS swizzle tables verifies that the resulting framebuffer alpha is `(depth >> 8) & 127` for representative 16-bit depths. The CT16 FBMSK conversion follows [PCSX2's software renderer](https://github.com/PCSX2/pcsx2/blob/master/pcsx2/GS/Renderers/SW/GSRendererSW.cpp). The fog sprite's TEST is GEQUAL at Z=`0x7fff`, with depth writes masked: it colors pixels whose adjusted GS depth is at most `0x7fff`. ALPHA `(Cd-Cs)*Ad/128+Cs` yields visibility `Ad/128`; farther pixels approach fog color. The sprite writes `field_0x14` to alpha independently of that visibility.
- Property flag `1` enables the effect; `4` skips the colored sprite while retaining depth adjustment and depth-to-alpha; `0x20` repeats the same signed depth-byte adjustment afterward, with saturation; it does not restore the original depth. Flags `2` and `8` do not change this effect body's color equation; `LargeObject` propagates flag `2`, and material submission separately consumes flag `8`. Scene transitions already interpolate `field_0xec` into the signed offset and interpolate RGB; they halve authored RGB into `field_0x8/c/10`, set `field_0x14=128`, and disable fog when the offset reaches 128. Native submission consumes these prepared values without advancing transitions.
- `SubmitFog` copies settings into an ordered RenderThread command after flushing scene materials. Recording ends the active pass, honors any pending scene clear, copies depth into a per-frame image, and runs the fog pass with explicit transfer, sampling, and depth-write dependencies. It captures both native and GS camera projection depth/W coefficients, reconstructs GS depth with their rational conversion, computes the byte adjustment and fog weight, and writes adjusted native depth with the inverse conversion. Unmodified depth retains its original floating-point value. Dual-source blending separates fog visibility from the alpha byte written to the framebuffer. Later draws resume with LOAD, and settings changes cannot alter queued fog commands. Transparent meshes without depth writes use background depth; depth-writing transparency uses its own depth. Framebuffer resize retires and recreates the depth snapshots and fog framebuffer. The independent actor preview has no scene-fog replay.
- Deliberate native approximation: the pass reproduces the depth ramp, sprite blend, alpha write, and signed depth adjustment directly, without replaying GS framebuffer aliasing. The shuffle also replaces blue bit 7, and `ed3DCorrectAlpha` patches specific swizzled rows near the framebuffer tail; these side effects are not reproduced. Native depth storage also does not reproduce PSMZ16 aliasing of 24/32-bit depth surfaces, original strip-edge coverage, GS integer color rounding, or different child-scene projections sharing one depth image. The recovered 16-bit path is the reference for this implementation. Runtime surface formats and PS2 captures must establish which of these differences affect real scenes before declaring parity.

Implementation notes (2026-10-07):

- **Fog does not trigger AA.** Fog calls `ed3DFlushAAEffectPlane` (`002ae8b0`), a signed, saturating green-byte depth adjustment shared by both effects. Scene dispatch calls the separate `ed3DFlushAAEffect` (`002b8640`) after fog, children, and the scene display list, only when packets were emitted, scene flag `0x80` is set, and `0x800` is clear. The original body also requires `BYTE_00448a70`, `gAALiasON`, a viewport, and dimensions 512x512 or 512x448.
- Ghidra recovery of the normal branch: undo one fog depth offset when fog is active; apply the AA depth offset; use `ed3DMoveRG2BA(..., true)` to expose depth as destination alpha; capture scene color to scratch; blur scratch; composite it back. Scratch is `DAT_00449580` in GS memory, not the heat-effect capture. Loaded settings at `00425020` are depth offset **-82**, blend constant **175**, debug-color flag 0, alternate-alpha flag 0, alternate-path flag 0, **eight blur draws**, composite mode 0, **radius one**, **256x256 scratch**, and PSMCT32.
- `FUN_002b7c50` copies the draw surface to scratch in sixteen strips using linear filtering. `FUN_002b76c0` samples that same scratch as a render target, shifts each draw by truncated `radius * cos/sin(2*pi*i/count)` texels, and blends `(Cs-Cd)*FIX/128+Cd`, with `FIX=floor(128/(i+2))`. Radius one thus reduces to cardinal shifts and zero shifts; this is an overlapping GS feedback blur, not multisample rasterization. `FUN_002b80e0` composites at sprite Z `0x7fff` with ZGEQUAL and masked depth writes. Normal mode 0 ALPHA `0x11` computes `(Cd-Cs)*Ad/128+Cs`: original color weighted by depth alpha, blurred scratch weighted by its inverse. The other composite modes and `FUN_002b7250` alternate branch are recovered but not reproduced by the approximation.
- **Rendering → Pipeline → Anti-Aliasing** persists **Off**, **PS2 approximation** (default), or **FXAA**. This is an explicit port override of the original disabled global and fixed hardware dimensions; it retains the scene flags, emitted-packet condition, viewport requirement, and `BYTE_00448a70`. It does not set `gAALiasON` or change PS2 builds. AA works with the native fog toggle disabled: the hook captures a fog offset only when the preceding scene fog was enabled.
- The PS2 approximation captures native scene RGB plus a fixed 256x256 linear resample, approximates the eight blur blends using an immutable scratch snapshot, and composites using the recovered depth mask and -82 offset. [GsProjection.h](../port/Windows/Renderer/include/GsProjection.h) supplies the original rational GS projection, retaining its W offset. One fog green-byte adjustment is undone in the sampled mask, including its saturating behavior; AA does not alter the actual depth attachment. Unlike the original channel shuffle/composite, both native choices preserve framebuffer alpha and depth for subsequent effects. GS in-place feedback, strip-edge/half-texel behavior, the 512x448 copy's vertical mapping, blue-bit/tail-row aliasing, alternate settings, and exact GS rounding remain approximations. An inset viewport clamps filter sampling to its region; the reduced capture can still mix colors at its boundary during downsampling.
- FXAA operates on the native-resolution color snapshot, independently of depth, with local-contrast rejection, horizontal/vertical edge classification, a bounded edge search, and subpixel filtering. It follows the algorithm described in [NVIDIA's FXAA white paper](https://developer.download.nvidia.com/assets/gamedev/files/sdk/11/FXAA_WhitePaper.pdf); it is a native implementation rather than a specific NVIDIA preset. UI submitted after the scene is unaffected. No temporal history, jitter, or motion vectors are introduced. MSAA would additionally require multisampled geometry/depth attachments and resolve rules for the renderer's framebuffer/depth effects; temporal methods would need history and motion information.
- Selecting PS2 approximation also exposes a persisted **Full Resolution PS2 AA Capture** toggle. The default remains the recovered 256x256 scratch approximation; enabling it filters the existing native-resolution color snapshot. The radius stays one capture texel, giving finer smoothing and less softness at higher render resolutions. The toggle is captured per submitted command, follows framebuffer resizing, and preserves the same depth mask, alpha, and depth behavior.
- AA captures its method, capture resolution, viewport, projection, and fog offset in an ordered RenderThread command. Each frame slot has independent snapshots and descriptor pools; reuse is synchronized after previous sampling, pools reset after the slot's fence, and framebuffer resources are recreated on resize. Continuation passes LOAD color/depth; a pending clear executes before capture. The second-camera preview does not replay scene AA, matching its current omission of scene fog.
- Selecting FXAA also exposes a persisted **FXAA Quality Multiplier**: **1x** (default), **2x**, or **4x**. These set the maximum edge search to 12, 24, or 48 steps per direction, with early exit when endpoints are found. They increase search effort for long edges at additional GPU cost; they are not MSAA sample counts, supersampling, or repeated full-screen passes. The multiplier is captured with each submitted AA command and does not alter the PS2 blur radius. The GPU regression checks that a finite long edge produces different results as each larger budget reaches farther along it, while preserving alpha/depth.
- Validation: x64-debug build, CTest, SPIR-V validation, and the opt-in `AntiAliasingRendering.DISABLED_ModesFogMaskQueueViewportAndResize` GPU test pass. The GPU test checks Off, depth-weighted PS2 filtering, foreground rejection, partial weights, FXAA edge filtering, flat colors, preserved alpha/depth, fog offset undo, queued geometry and captured settings, viewport exclusion, and 768x448 resizing.
